1.1.1 Non-text Content の解説

不適合の可能性が高い: 確認してください

ℹ invalid-field-error-message (要確認、重大度: 重大)
WCAG 3.3.1
セレクター: #email
このフィールドは無効とマークされていますが、aria-errormessage が指すエラーメッセージは隠れています。 — フィールドが無効な間は、エラーメッセージを表示してください。

不適合の可能性が高い: フィールドに結び付けられたエラーメッセージが非表示のため、エラーはおそらく伝えられていません。

確認方法
  1. 利用者と同じ方法でフィールドを無効な状態にしてください (フォームを空のまま送信するか、誤った値を入力します)。
  2. フィールドが指すエラーメッセージ (aria-errormessage によるもの) を探し、画面上に表示されるか確認してください。
  3. 表示されない場合は、ラベル内、フィールドの隣、またはフォーム上部の概要に、何が誤っているかを伝えるテキストがないか探してください。
  4. スクリーンリーダーでフィールドに移動し、エラーが読み上げられるか聞いてください。

適合: aria-errormessage が示すメッセージでなくても、フィールドに結び付いたどこかでエラーがテキストで表示され、読み上げられます。

不適合: どのフィールドがなぜ誤っているかを伝えるテキストがないか、スクリーンリーダーの利用者に伝わらないため、WCAG 3.3.1 を満たしません。

3.3.1 Error Identification の解説

ℹ img-alt-quality (要確認、重大度: 軽微)
WCAG 1.1.1
セレクター: html > body > main > img:nth-of-type(2)
この <img> のテキストによる代替はファイル名のように見えます。 — ファイル名は、画像を見られない人にとって画像について何も伝えません (WCAG 失敗例 F30)。画像が何を示しているか、リンクやボタンであればどこへ移動し何をするのかを伝えるテキストに置き換えてください。ファイル一覧のスクリーンショットのように、ファイル名そのものが画像に写っている内容である場合に限り、そのままで構いません。

不適合の可能性が高い: ファイル名、Web アドレス、汎用的な語では、画像が何を示しているかは伝わりません。 注意: その語の画像のように、その語が画像の示すすべてである場合もあります。

確認方法
  1. レポートに示された画像を見つけ、その代替テキストを読んでください (疑わしいと判断された理由があれば、レポートに示されています)。
  2. 画像とその文脈を見て、ページにとって重要な何を示しているかを検討してください。
  3. alt がそれを伝えているか判断してください。ファイル名、Web アドレス、「画像」のような汎用的な言葉は伝えているとは言えません。

適合: 代替テキストが、利用者に必要な画像の内容を、文脈に合った言葉で伝えています。

不適合: 代替テキストがファイル名、アドレス、汎用的な言葉などであり、画像の内容を伝えていないため、WCAG 1.1.1 を満たしません (F30)。

ℹ duplicate-id (要確認、重大度: 中程度) × 2
WCAG 4.1.1
セレクター: html > body > main > form > input:nth-of-type(2)
id「code」が、同じツリー内の 2 個の要素で使われています。 — 要素ごとに固有の id を付けてください。id が重複すると、<label for>、フラグメントリンク、getElementById、ID を参照するすべての属性が、最初に一致した要素しか参照しなくなり、正しく機能しません。

適合の可能性が高い: WCAG 2.2 では、これを検出した達成基準が削除されています。 注意: 欠陥そのものは、それに依存する機能を引き続き損ない、この達成基準を維持する規格では不適合となります。

確認方法
  1. レポートに示された要素を調べ、共有されている id を控えてください。
  2. その id を参照しているもの (label の for、aria-labelledby などの aria-* 属性、#the-id へのリンク) があるか確認してください。
  3. 参照しているものがあれば、その参照をたどり (ラベルやリンクをクリックするか、アクセシビリティ ペインで名前を読み)、意図された要素に届くことを確認してください。
  4. 監査が適用する WCAG のバージョンと規格を確認してください。WCAG 2.2、または 2023 年の正誤表を適用した 2.0/2.1 では、HTML について 4.1.1 は満たされます。

適合: 重複によって壊れるものはなく (参照は意図された要素に届き)、監査は WCAG 2.2 または正誤表を適用した 2.0/2.1 を使っているため、4.1.1 は満たされます。

不適合: ラベル、ARIA の参照、またはリンクが誤った要素に届く (WCAG 1.3.1 または 4.1.2) か、EN 301 549 V3.2.1 のように 4.1.1 の文言を維持する規格に基づく監査であり、その場合 id の重複は 4.1.1 を満たしません (F77)。
