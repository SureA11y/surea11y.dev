始める前に

これらの手順では、何を確認し、どのように判定するかを説明しています。どのブラウザーや支援技術を使う場合でも、いくつかの習慣を守ることで結果の信頼性が高まります。

  • 利用者が使っているブラウザーとスクリーンリーダーの組み合わせを、少なくとも 2 つ使ってテストしてください。よく使われる組み合わせは、Windows では NVDA と Firefox または Chrome、JAWS と Chrome、macOS と iOS では VoiceOver と Safari、Android では TalkBack と Chrome です。読み上げる内容はスクリーンリーダーやブラウザーによって異なるため、ある組み合わせでの結果がすべての組み合わせに当てはまるわけではありません。結果が食い違う場合は、どの組み合わせで不合格になったかを記録してください。
  • キーボードのテストは、スクリーンリーダーをオフにして行ってください。スクリーンリーダーはブラウズモードで、キーボードだけでは到達できない要素も作動させられるため、キーボードの問題が隠れてしまいます。
  • Mac では、システム設定の [キーボード] で「キーボードナビゲーション」をオンにし、Safari の詳細設定で、Tab キーを押したときに Web ページ上の各項目を強調表示するオプションをオンにしてください。これらがオフのままだと、Tab キーでリンクや一部のコントロールが飛ばされ、実際には存在しない不合格を記録することになります。
  • ページの先頭からキーボードでの確認を始めるには、ページを再読み込みしてどこもクリックせずに Tab キーを押すか、最初のリンクやコントロールのすぐ上の何もない部分をクリックしてください。アドレスバーから始める方法は確実ではありません。ブラウザーによっては、フォーカスがまず自身のツールバーやアドレスバーの候補を移動するためです。
  • アクセシビリティツリーを表示する場所はブラウザーごとに異なります。Chrome と Edge では [Elements] パネルのアクセシビリティ ペイン (ページ全体を見るには、ページ全体のアクセシビリティツリーをオンにします)、Firefox ではアクセシビリティインスペクター、Safari では [要素] タブの [ノード] パネルにあるアクセシビリティのセクションです。手順に「開発者ツールのアクセシビリティ ペイン」とある場合は、テストしているブラウザーのものを使ってください。
  • 開発者ツールのデバイスツールバーはビューポートのサイズを変更しますが、実際のスマートフォンのズーム、画面の回転、ジェスチャ、スクリーンリーダーは再現しません。モバイルでの結果は実機で確認してください。
  • ページを最初に読み込んだときだけでなく、ページがとりうる各状態をテストしてください。メニューやダイアログを開いた状態、エラーメッセージ、空のリストや項目の多いリスト、ログイン時とログアウト時の表示などです。
  • 「手がかりのみ」と示されたルールは、それだけでは判定できません。報告された内容は、手作業で確認すべき箇所の一覧として扱ってください。

1 知覚可能

1.1 テキストによる代替

1.1.1 非テキストコンテンツ

レベル A

何かを伝える非テキストコンテンツにテキストによる代替がある
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. 写真、アイコン、ロゴ、グラフ、地図、図、動画のポスター画像、ボタンやリンクの中の画像など、テキストでないコンテンツをページ全体から探してください。
  2. それぞれを開発者ツールの [Elements] パネルで選択し、アクセシビリティ ペインで Name を読んでください。
  3. 名前がなく、支援技術から隠されてもいない (alt=""、aria-hidden="true"、role="presentation"、または CSS の背景によって) ものをすべて控えてください。
  4. 背景画像、アイコンフォント、content プロパティで追加された画像など、CSS だけで表示される情報も探してください。読むべき alt 属性がないため、それぞれを調べ、表示されている内容がスクリーンリーダーの読み上げるテキストでも提供されているか確認してください。
  5. グラフや地図など、短い言葉では説明できないコンテンツについては、名前が少なくともそれが何であるかを示し、より詳しい説明がページ上にあるか、隣にリンクされていることを確認してください。
合格の条件
利用者に必要なすべての非テキストコンテンツにテキストによる代替があるか、装飾であるため支援技術から隠されています。
不合格の条件
何かを伝える非テキストコンテンツにテキストによる代替がなく、スクリーンリーダーの利用者には名前のない画像が示されるか何も示されないため、WCAG 1.1.1 を満たしません。

これを検査するルール：img-alt-present, role-img-text-alternative-present, canvas-text-alternative-present, embed-text-alternative-present, svg-text-alternative-present, svg-image-text-alternative-present, object-text-alternative-present, video-poster-text-alternative-present, meter-name-present, progressbar-name-present

この手順では次も評価します：

  • <img> に alt 属性がある
  • role="img" にテキストによる代替がある
  • <canvas> に代替コンテンツまたはアクセシブルな名前がある
  • <embed> に代替コンテンツまたはアクセシブルな名前がある
  • 公開されている <svg> にテキストによる代替の手段がある
  • インラインの <svg> に <title> またはアクセシブルな名前がある
  • SVG の <image> にテキストによる代替の手段がある
  • <object> に代替コンテンツまたはアクセシブルな名前がある
  • <video poster> にテキストによる代替の手段がある
  • role="meter" の要素がアクセシブルな名前を公開している
  • role="progressbar" の要素がアクセシブルな名前を公開している
コントロールとして使われる画像やアイコンに、その働きを示す名前がある
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. ホームへリンクするロゴ、検索の虫眼鏡、ダイアログを閉じる×印など、内容が画像やアイコンだけのリンク、ボタン、その他のコントロールをすべて見つけてください。
  2. それぞれを開発者ツールの [Elements] パネルで選択し、アクセシビリティ ペインで Name を読んでください。
  3. 名前が、画像に写っているもの (「虫眼鏡」) やファイル名ではなく、コントロールの働きや移動先 (「検索」「閉じる」「ホーム」) を示しているか確認してください。
合格の条件
画像やアイコンでできたすべてのコントロールに、その働きや移動先を示す名前があります。
不合格の条件
画像やアイコンでできたコントロールに名前がないか、名前が働きではなく画像を説明しているため、WCAG 1.1.1 を満たしません。

これを検査するルール：input-image-alt-present, area-alt-present

この手順では次も評価します：

  • <input type="image"> に alt 属性がある
  • <area> に alt 属性がある
装飾的な画像だけが支援技術から隠されている
  • 人だけが確認できる
  • 必要なもの：ブラウザーの開発者ツール
  1. 枠線、区切り線、背景画像、飾り、隣のテキストがすでに内容を伝えている画像など、装飾のためだけの画像、アイコン、グラフィックをページから探してください。
  2. それぞれを開発者ツールの [Elements] パネルで選択し、アクセシビリティ ペインで無視されている (alt=""、aria-hidden="true"、role="presentation"、または CSS の背景) ことを確認してください。
  3. ページ内に描かれた装飾的な SVG については、aria-hidden="true" があることを確認してください。これがないと、ブラウザーとスクリーンリーダーの組み合わせによっては、名前のない画像として読み上げたり、中のテキストを読んだりします。
  4. 次に逆の確認をしてください。そのように隠されている各画像について、なくなった場合に利用者が何か (情報、ラベル、グラフのデータ) を失うかを考えます。
合格の条件
装飾的な画像は支援技術から隠されており、隠されている画像はすべて本当に装飾です。
不合格の条件
装飾的な画像が (多くの場合ファイル名で) 読み上げられるか、情報を伝える画像が支援技術から隠されているため、WCAG 1.1.1 を満たしません。
各テキストによる代替が、画像が伝えるものを伝えている
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. テキストによる代替を持つ各画像やその他の非テキストコンテンツについて、代替 (開発者ツールのアクセシビリティ ペインの Name) を読み、ページ上のその位置でコンテンツを見てください。
  2. その位置でコンテンツが読み手に何を伝えているかを考え、代替が同じものを伝えているか確認してください。画像化された文字ならその文字、写真ならそれが示す要点、グラフならそれが示す事実です。
  3. グラフや図などの複雑な画像に対して代替がその名前しか示していない場合は、詳細が隣のキャプション、テキスト、表、または横のリンクにあり、スクリーンリーダーの利用者が画像からそれを見つけられることを確認してください。
  4. ファイル名、ウェブアドレス、「画像」「写真」のような言葉である代替や、すぐ隣のテキストを繰り返している代替を控えてください。
  5. 各代替の言語を確認してください。ページの言語で書かれているか、その言語が指定されていることが望ましいです。
合格の条件
各テキストによる代替が、その位置でコンテンツが伝えるものを、直接、またはスクリーンリーダーの利用者がそこからたどれる説明によって伝えています。
不合格の条件
ファイル名、汎用的な言葉、データがどこにも示されていないグラフの名前など、テキストによる代替がコンテンツの伝えるものを伝えていないため、WCAG 1.1.1 を満たしません (F30)。

これを検査するルール：area-alt-quality, canvas-text-alternative-quality, embed-text-alternative-quality, img-alt-decorative, img-alt-quality, input-image-alt-decorative, input-image-alt-quality, object-text-alternative-quality, svg-text-alternative-quality

この手順では次も評価します：

  • テキストによる代替が適切で同等である
  • 代替テキストの疑わしいパターン (ファイル名、仮の文字列など)
CAPTCHA が目的を示し、別の感覚を使う形式も提供している
  • 人だけが確認できる
  • 必要なもの：スクリーンリーダー
  1. 入力させる歪んだ文字、選ばせる画像、ドラッグさせるパズルなど、ページが人とプログラムを見分けるために使っているテストを見つけてください。
  2. 答えを明かすことなく、それが何であり何をすればよいかを示すテキストによる代替があることを確認してください。
  3. 視覚によるテストに対する音声版のように別の感覚を使う形式、またはメールで送られるコードのようにまったく別の方法が提供されていることを確認してください。
  4. スクリーンリーダーとキーボードで、その別の形式を試してください。
合格の条件
ページにそのようなテストがないか、テストが何であるかを示し、別の感覚を使って完了できる形式を提供しています。
不合格の条件
テストが見ることによってしか (または聞くことによってしか) 合格できないか、それが何であるかを示すテキストがないため、WCAG 1.1.1 を満たしません。

1.2 時間ベースのメディア

1.2.1 音声だけ及び映像だけ (収録済み)

レベル A

収録済みの音声だけ及び映像だけのメディアに、トランスクリプトまたは同等の代替がある
  • ルールが一部を判定する
  • 必要なもの：ブラウザーのみ
  1. フレーム内のものも含め、ページ上のすべての音声プレーヤーと音のない動画を見つけ、それぞれを再生してください。
  2. 音声については、プレーヤーの隣やページのほかの場所に、トランスクリプトまたはそのリンクがあるか探してください。
  3. 音のない動画については、トランスクリプト、または表示されるすべてを説明する音声版があり、ページからキーボードで見つけて再生できるか探してください。
  4. それぞれの代替をメディアと比べ、発話、重要な音、表示される内容について、同じ情報を伝えているか確認してください。
  5. それ自体がページ上のテキストに対する代替であり、そのことが明示されているメディアは除外してください。
合格の条件
収録済みの音声だけ又は映像だけの各メディアに、同じ内容を伝えるトランスクリプト (映像の場合は音声版でも可) があるか、ページ上のテキストに対する代替であることが明示されています。
不合格の条件
収録済みの音声だけのメディアにトランスクリプトがないか、収録済みの映像だけのメディアに、同じ情報を伝えるトランスクリプトも音声版もないため、WCAG 1.2.1 を満たしません。

これを検査するルール：media-alternative-transcript-evidence

1.2.2 キャプション (収録済み)

レベル A

音声付きの収録済み動画にキャプションがある
  • 人だけが確認できる
  • 必要なもの：ブラウザーのみ
  1. フレーム内のものやほかのサイトのプレーヤーも含め、ページ上の音声付きの収録済み動画をすべて見つけてください。
  2. それぞれを音を出して再生し、その音声が情報 (発話や重要な音) を伝えているかを控えてください。
  3. 情報を伝えている場合は、プレーヤーの CC ボタン、映像に焼き込まれたキャプション、または隣にリンクされた同じ動画のキャプション付き版など、キャプションを探してください。トランスクリプトだけではキャプションの代わりになりません。
  4. それ自体がページ上のテキストに対する代替であり、そのことが明示されている動画は除外してください。
合格の条件
音声が情報を伝える収録済みの動画すべてに、その場で、または隣にリンクされたキャプション付き版でキャプションがあるか、ページ上のテキストに対する代替であることが明示されています。
不合格の条件
収録済みの動画にせりふや重要な音があるのに、トランスクリプトが提供されていても、その場にもリンクされたキャプション付き版にもキャプションがないため、WCAG 1.2.2 を満たしません。

これを検査するルール：video-caption

キャプションが、すべてのせりふ、話者、重要な音を、動画と同期して伝えている
  • 人だけが確認できる
  • 必要なもの：ブラウザーのみ
  1. キャプション付きの各動画を、音を出し、キャプションをオンにして再生してください。
  2. 最初から最後まで、キャプションを話されている内容や聞こえる音と比べてください。
  3. キャプションがすべてのせりふを伝え、話者がわかりにくい場合は誰が話しているかを示し、重要な音 (音楽、警報音、笑い声) を説明しており、映像と同期し続けていることを確認してください。
  4. 自動生成されたキャプションは注意して扱ってください。名前、数字、句読点を誤ることが多く、音を説明しないため、編集しない限りこの達成基準を満たすことはまれです。
合格の条件
キャプションが、すべてのせりふ、必要な場合は話者、重要な音を、動画と同期して伝えています。
不合格の条件
キャプションがせりふや重要な音を省いている、必要な場合に誰が話しているかを示していない、または動画との同期がずれているため、WCAG 1.2.2 を満たしません (F8)。

1.3 適応可能

1.3.1 情報及び関係性

レベル A

見出しに見えるテキストが、ページのアウトラインに合ったレベルの見出しとしてマークアップされている
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー
  1. ページを見て、周囲のテキストより大きいか太く、後に続く内容を導入している、見出しとして機能するテキストをすべて控えてください。
  2. それぞれについて、開発者ツールの [Elements] パネルで、<h1> から <h6> のいずれかであるか、aria-level 付きの role="heading" を持つことを確認してください。
  3. 逆も確認してください。ページ上の各見出し要素が、テキストを大きくするためだけに使われているのではなく、内容を導入していることを確認します。
  4. スクリーンリーダーの見出し一覧、HeadingsMap などのブラウザー拡張機能、またはアクセシビリティ ペインで見出しを一覧にし、そのレベルがページの見た目の構造と一致しているか確認してください。セクションの小見出しは、そのセクションの見出しと同じレベルやそれより上ではなく、その下に位置します。h2 の後に h4 が続くなど、レベルが飛んでいるだけであれば、入れ子が正しい限りこの達成基準を満たさないことにはなりません。ベストプラクティスの問題として記録してください。
合格の条件
見た目の見出しはすべて見出しとしてマークアップされ、見出し要素はすべて実際に見出しであり、レベルがページのアウトラインに従っています。
不合格の条件
見出しに見えるテキストが通常のテキストである、見出し要素が大きさのためだけに使われている、またはレベルがアウトラインと矛盾しているため、スクリーンリーダーの利用者がセクションを見つけたりたどったりできず、WCAG 1.3.1 を満たしません。

これを検査するルール：p-as-heading

この手順では次も評価します：

  • 本来の見出し要素が必要な可能性がある、太字で見出しの大きさの <p> のテキスト (手がかりのみ)
リストとして表示されるコンテンツがリストとしてマークアップされている
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. メニュー、手順、リンクのグループなど、行頭記号や番号、または同じレイアウトで横や縦に並んだ項目として、リストのように表示されているコンテンツをページから探してください。
  2. それぞれについて、開発者ツールの [Elements] パネルで、<ul>、<ol>、<dl> のいずれかである (または role="listitem" の項目を持つ role="list" がある) ことを確認してください。
  3. 各リストの直接の子がリスト項目だけであり、各リスト項目がリストの中にあることを確認してください。
  4. VoiceOver と Safari でテストする場合、list-style: none で行頭記号を消したリストは、role="list" がない限り Safari がリストとして公開しないことに注意してください。これはページの不備ではなくブラウザーの方針ですが、リストの構造が利用者にとって重要な場合は控えてください。
合格の条件
リストとして表示されるコンテンツがリストとしてマークアップされ、リストのマークアップに欠けがありません。
不合格の条件
リストとして表示されるコンテンツが段落、改行、div の連続であるか、リストのマークアップが壊れているため、スクリーンリーダーがリストであることや項目数を伝えず、WCAG 1.3.1 を満たしません。

これを検査するルール：list-children-valid, listitem-parent-valid, definition-list-children-valid, dlitem-parent-valid

この手順では次も評価します：

  • <ul>/<ol> の直接の子が <li> (または <script>/<template>) だけである
  • <li> 要素がリストのコンテナー (<ul>/<ol>/role="list") に含まれている
  • <dl> の直接の子が、<dt>/<dd> のグループ (1 つの <div> で囲んでもよい)、<script>、<template>、<style> だけである
  • <dt>/<dd> 要素が、直接または囲みの <div> 1 つを介して <dl> に含まれている
データテーブルの見出しとキャプションがマークアップされ、レイアウトのためだけの表には見出しのマークアップがない
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー
  1. ページ上のすべての表と、表を使わずに作られたデータのグリッドをすべて見つけてください。
  2. データの表については、開発者ツールの [Elements] パネルで、見出しセルが <th> であり (行見出しか列見出しかが明らかでない場合は scope 付き)、表の上に表示されているタイトルが <caption> であることを確認してください。

  4. スクリーンリーダーでいくつかのデータセルを移動し、見出しが一緒に読み上げられることを確認してください。
  5. レイアウトのためだけに使われている表については、<th>、<caption>、summary がないことを確認してください。
合格の条件
データは見出しとキャプションがマークアップされた表に入っており、スクリーンリーダーが各セルの見出しを読み上げ、レイアウト用の表には見出しのマークアップがありません。
不合格の条件
データの表に見出しのマークアップがないかセルに偽のキャプションがある、データが表を使わずにグリッド状に配置されている、またはレイアウト用の表がデータとしてマークアップされているため、WCAG 1.3.1 を満たしません。

これを検査するルール：table-headers-attr-valid, table-th-has-data-cells, table-fake-caption, td-has-header

この手順では次も評価します：

  • 表のセルの headers 属性が、同じ表の中の有効な <th> セルを参照している
  • <th> セルを持つ表に、それが説明するデータセルもある
  • 本来の <caption> の代わりになっている可能性がある、表の 1 行目のセル (手がかりのみ)
  • 大きく単純な表のデータセルに、関連付けられた見出しがある
フォームフィールドが見えるラベルに、フィールドのグループがグループ名を示すテキストに関連付けられている
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー
  1. テキストフィールド、チェックボックス、ラジオボタン、ドロップダウン、カスタムコントロールなど、ページ上のすべてのフォームフィールドを見つけてください。
  2. それぞれを開発者ツールの [Elements] パネルで選択し、アクセシビリティ ペインの Name に見えるラベルが含まれていることを確認してください。
  3. ラジオボタンや 3 つに分かれた日付など、1 つの質問に属するフィールドのグループについては、各フィールドとともに質問が読み上げられるように、グループが <legend> 付きの <fieldset> であるか、名前付きの role="group" を持つことを確認してください。
  4. フィールドの隣に表示される指示 (形式、必須の印) が、aria-describedby でフィールドに関連付けられているか、ラベルの中にあることを確認してください。
合格の条件
各フィールドの名前に見えるラベルが含まれ、フィールドのグループには質問による名前があり、フィールドの指示がフィールドに関連付けられています。
不合格の条件
フィールドが関連付けられていない近くのテキストだけでラベル付けされているか、グループの質問がフィールドに関連付けられていないため、スクリーンリーダーがフィールドの目的を伝えずに読み上げ、WCAG 1.3.1 を満たしません。

これを検査するルール：form-control-programmatic-label-present

この手順では次も評価します：

  • フォームコントロールにプログラムで解釈できるラベル (label/aria-label/aria-labelledby/title/placeholder) がある
  • フォームコントロールのラベルが適切である
ARIA のロールと関係性が、ページの見た目と同じ構造を伝えている
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. カスタムのメニュー、タブ、ツリー、グリッド、リスト、リストボックスなど、ARIA のロールで作られたページの部分を見つけてください。
  2. それぞれについて開発者ツールのアクセシビリティツリーを開き、示される構造が画面上の表示と一致しているか確認してください。tablist が tab を含み、menu が menuitem を含み、grid が row と cell を含んでいることなどです。
  3. ロールを持つ要素に、そのロールが必要とする親や子が欠けていないこと、また aria-owns を使っている場合は各要素に所有者が 1 つだけであることを確認してください。
  4. <body> が aria-hidden="true" で隠されていないことを確認してください。
合格の条件
アクセシビリティツリーがページの見た目の構造を伝えており、すべてのロールがそのロールに必要な位置にあります。
不合格の条件
ロールに必須の親や子が欠けている、二重に所有されている、またはページがツリーから隠されているため、支援技術が画面と一致しない構造を伝え、WCAG 1.3.1 を満たしません。

これを検査するルール：aria-hidden-body, aria-required-children, aria-prohibited-children, aria-required-parent, aria-roles-valid, aria-owns-valid

この手順では次も評価します：

  • 文書の <body> に aria-hidden="true" がない
  • コンテナーのロール (list、listbox、menu、table、tablist、tree など) が、必須の子ロールを少なくとも 1 つ所有している
  • コンテナーのロールが、許可されていないロールを持つアクセシビリティツリー上の子を所有していない
  • 特定のコンテキストロールを必要とするロール (listitem、option、tab、treeitem、row、cell など) に、適切な祖先または所有者がある
  • 明示的な role 属性が抽象ロールでない実在の ARIA ロールに解決され、それが伝える構造がプログラムによる解釈が可能である
  • aria-owns が各要素に所有者を 1 つだけ与え、所有者の祖先を所有させていない
太字、色、位置、アスタリスクなど、スタイルやレイアウトで示される意味が、マークアップまたはテキストでも示されている
  • 人だけが確認できる
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー
  1. アスタリスクや色で示された必須フィールド、強調や取り消し線の付いた語、スタイルで示された選択中の項目、枠で区別されたテキストなど、見た目だけで示されている意味を探してください。
  2. それぞれについて、同じ意味がマークアップ (required、aria-current、<em>、<del> など) またはテキスト自体 (「必須」「現在のページ」) にあるか確認してください。
  3. CSS の content プロパティで追加されたテキストやアイコンを確認してください。スクリーンリーダーがそれを読むかどうかはブラウザーによって異なるため、CSS だけで追加される情報は、マークアップまたはテキストにもある必要があります。
  4. それらの部分をスクリーンリーダーで読み、スタイルが示す内容が読み上げられることを確認してください。
合格の条件
スタイルやレイアウトが伝える内容は、すべてマークアップまたはテキストにもあります。
不合格の条件
色だけ、または説明のないアスタリスクだけで示された必須フィールドなど、意味がスタイルや位置だけで示されているため、スクリーンリーダーの利用者がそれを見落とし、WCAG 1.3.1 を満たしません。

1.3.4 向き (orientation)

レベル AA

  • ルールが一部を判定する

不合格の条件

1.3.5 入力目的の特定

不合格の条件

  • 空でない autocomplete 属性が有効な自動入力の値である

1.4.3 コントラスト (最低限)

レベル AA

テキストと背景のコントラスト比が 4.5:1 以上 (大きな文字は 3:1 以上) である
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. 薄いグレーのテキスト、色付きのパネル上のテキスト、プレースホルダー、画像やグラデーションに重なるテキスト、ボタン内のテキストなど、背景に対して薄く見えるテキストをページから探してください。
  2. それぞれを調べ、開発者ツールの [Styles] ペインで色の見本をクリックしてください。カラーピッカーに背景とのコントラスト比が表示されます。
  3. カラーピッカーは、CSS で指定された背景色に対して測定します。テキストが画像、グラデーション、半透明のレイヤーの上にある場合や、テキストの色が opacity やブレンドモードによって決まる場合は、ピッカーの数値は信頼できないため、代わりに次の手順を使ってください。
  4. 背景が画像、グラデーション、半透明のレイヤーである場合は、コントラスト計算ツールを使い、テキストが最も見えにくい部分の背景に対してテキストを測定してください。
  5. コントラスト比が 4.5:1 以上、大きな文字 (24 ピクセル (18 ポイント) 以上、または 18.66 ピクセル (14 ポイント) 以上の太字) では 3:1 以上であることを確認してください。
  6. 結果を四捨五入しないでください。4.49:1 は不合格です。状態によってコントラストが下がることがあるため、ホバー時、フォーカス時、選択時などのほかの状態のテキストも確認してください。
  7. ロゴやブランド名、無効になっているコントロールのテキスト、装飾にすぎないテキストや誰にも見えないテキスト、写真の中の道路標識のようにほかの重要なコンテンツを含む画像の一部であるテキストは除外してください。
合格の条件
すべてのテキストと文字画像の背景とのコントラスト比が 4.5:1 以上 (大きな文字は 3:1 以上) です。
不合格の条件
テキストと背景のコントラスト比が 4.5:1 (大きな文字は 3:1) 未満で、ロービジョンの人が読めないため、WCAG 1.4.3 を満たしません。

これを検査するルール：contrast-minimum, contrast-computable

この手順では次も評価します：

  • 1.4.3 のテキストのコントラストを CSS から計算できる (画像、グラデーション、ブレンドによる不確定要素がない)

1.4.12 テキストの間隔

レベル AA

style 属性で強制された間隔が、テキストへの利用者の間隔の適用を妨げていない
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. 開発者ツールの [Elements] パネルで、ページのマークアップから !important を検索し (Ctrl+F、Mac では Cmd+F)、line-height、letter-spacing、word-spacing を指定している style 属性内の一致箇所をすべて控えてください。
  2. それぞれについて、[Computed] タブで結果の値を読み、line-height はフォントサイズの 1.5 倍、letter-spacing は 0.12 倍、word-spacing は 0.16 倍と比べてください。
  3. 値がそれより小さい場合は、ウィンドウの幅を 320 CSS ピクセルまで狭め、そのテキストが 2 行以上に折り返すか確認してください。
  4. 開発者ツールの [Styles] ペインで、* に line-height: 1.5 !important; letter-spacing: 0.12em !important; word-spacing: 0.16em !important を指定するスタイルルールと、p に margin-bottom: 2em !important を指定するルールを新たに追加してください。style 属性が優先されるため、その要素は自身の値を保ちます。
  5. そのテキストが切り取られる、ほかのテキストと重なる、または隠れるかを確認してください。
合格の条件
折り返すテキストに対してそれらの値を下回る間隔を強制している style 属性はないか、強制されたテキストが間隔を適用してもすべて表示されます。
不合格の条件
折り返すテキストに対して style 属性がそれらの値を下回る間隔を強制しているため、ブックマークレットやブラウザー拡張機能で利用者の間隔を適用できず、その間隔ではテキストが重なるか切り取られ、WCAG 1.4.12 を満たしません。

これを検査するルール：avoid-inline-spacing

1.4.12 の間隔を適用しても、テキストが切り取られたり重なったりしない (ブラウザーで測定)
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, キーボード
  1. 開発者ツールの [Styles] ペインで、* に line-height: 1.5 !important; letter-spacing: 0.12em !important; word-spacing: 0.16em !important を指定するスタイルルールと、p に margin-bottom: 2em !important を指定するルールを新たに追加してください。[Styles] ペインで追加したルールは、ページのセキュリティポリシーによってブロックされません。
  2. ページ全体をスクロールし、切り取られる、ほかのテキストと重なる、または消えるテキストを探してください。画像の一部であるテキストは対象外です。
  3. ほかの確認で使う幅でも同じことを行ってください。テキストが最も折り返し、最も切り取られやすい幅 320 CSS ピクセルも含めます。
  4. テキストが切り取られている場合は、「続きを読む」リンクや枠を広げるボタンなど、テキスト全体を表示する手段をページが提供しているか確認してください。キーボードで操作でき、間隔を適用したままでテキスト全体を表示できる場合にだけ認めます。
合格の条件
すべてのテキストが見えて読める状態を保っているか、切り取られたテキストをキーボードで全文表示できます。
不合格の条件
間隔を適用するとテキストの一部が切り取られる、重なる、または失われ、別の方法で全文を表示することもできないため、WCAG 1.4.12 を満たしません。

これを検査するルール：text-spacing-content-loss

1.4.12 の間隔を適用しても、コントロール、メニュー、フォームが機能し続け、すべてのテキストを表示する
  • 人だけが確認できる
  • 必要なもの：ブラウザーの開発者ツール, キーボード, マウスなどのポインティングデバイス
  1. 開発者ツールの [Styles] ペインで、* に line-height: 1.5 !important; letter-spacing: 0.12em !important; word-spacing: 0.16em !important を指定するスタイルルールと、p に margin-bottom: 2em !important を指定するルールを新たに追加してください。
  2. ページ上の各コントロールを操作してください。メニューやドロップダウンを開き、フォームに入力して送信し、タブを切り替え、ダイアログを開閉します。
  3. それぞれが引き続き反応すること、位置がずれたテキストがコントロールを覆っていないこと、すべてのラベルとボタンがテキストをすべて表示していることを確認してください。
合格の条件
間隔を適用しても、すべてのコントロールが引き続き機能し、テキストをすべて表示しています。
不合格の条件
間隔を適用すると、コントロールが機能しなくなる、覆われて操作できなくなる、または働きを示すテキストが失われるため、WCAG 1.4.12 を満たしません。
1.4.12 の間隔を適用しても、操作後にだけ表示されるコンテンツ (メニュー、ダイアログ、タブ、メッセージ) がすべてのテキストを保つ
  • 人だけが確認できる
  • 必要なもの：ブラウザーの開発者ツール, キーボード, マウスなどのポインティングデバイス
  1. 開発者ツールの [Styles] ペインで、* に line-height: 1.5 !important; letter-spacing: 0.12em !important; word-spacing: 0.16em !important を指定するスタイルルールと、p に margin-bottom: 2em !important を指定するルールを新たに追加してください。
  2. 何かを操作した後にだけページが表示するコンテンツを表示させてください。各メニューとダイアログを開き、各タブに切り替え、折りたたまれた各セクションを展開し、各ツールチップを表示し、誤りを含むフォームを送信してエラーメッセージを表示します。
  3. ページ本体と同様に、それぞれについて、切り取られる、ほかのテキストと重なる、または消えるテキストがないか確認してください。
  4. テキストが切り取られている場合は、「続きを読む」リンクや枠を広げるボタンなど、テキスト全体を表示する手段をページが提供しているか確認してください。キーボードで操作でき、間隔を適用したままでテキスト全体を表示できる場合にだけ認めます。
合格の条件
操作後に表示されるコンテンツが、間隔を適用してもすべてのテキストを見えて読める状態に保っているか、切り取られたテキストをキーボードで全文表示できます。
不合格の条件

2.1.1 キーボード

レベル A

  • 人だけが確認できる
  • 必要なもの：キーボード
  1. スクリーンリーダーをすべてオフにしてください。スクリーンリーダーはブラウズモードで、キーボードだけでは到達できない要素も作動させられるため、不合格が隠れてしまいます。

  3. ポインターでクリックやドラッグができるものと比べ、コントロール、メニュー項目、スクロール可能なボックス、地図の一部、カスタムウィジェットなど、キーボードで一度も到達できないものを控えてください。
  4. 各コントロールをキーボードで操作してください。作動させるには Enter または Space、メニュー、タブ、リスト、スライダーの中では矢印キー、開いたものを閉じるには Escape を使います。
  5. カスタムウィジェットについては、タブリストでの矢印キーなど、その種類のウィジェットについて WAI-ARIA Authoring Practices が示すキーと比べてください。一般的でないキーでしか機能しないウィジェットも、ページがそのキーを説明していればこの達成基準を満たす場合がありますが、ユーザビリティの問題として記録してください。
  6. キーボードで到達や操作ができないものがある場合は、カルーセルの前へ・次へボタンのように、同じことをキーボードだけで行える別の手段をページが提供しているか確認してください。ポインターでできることをすべて行える場合にだけ認めます。

合格の条件

不合格の条件

この手順では次も評価します：

  • tabindex="-1" を持つ同一オリジンのフレームに、フォーカス可能なコンテンツがない
  • <img> がサーバーサイドイメージマップ (ismap) を使っていない
  • フォーカス可能な子孫を持たない、CSS でスクロール可能な領域自体がキーボードフォーカスを受け取れる (手がかりのみ。実際にあふれるかは静的には判断できない)
  • ポインター専用のインラインイベントハンドラーに、キーボードで到達できる同等の手段がある (手がかりのみ。JS で追加されたリスナーは静的には見えない)
  • ネイティブのコントロールでない要素のインラインのクリックハンドラーに、キーボードで到達して実行できる
  • ウィジェットのロールを持つ要素、または複合ウィジェットの項目の 1 つがタブ順序に含まれている (手がかりのみ。スクリプトがマークアップに現れない方法でフォーカスを移動することがある)
  • インラインのフォーカスハンドラーが、フォーカスを受け取った要素からフォーカスを外さない (手がかりのみ。スクリプトから追加されたリスナーは静的には見えない)

  • 必要なもの：ブラウザーのみ

  2. 記事の見出しや手続きの段階 (「お届け先住所 - ご注文手続き - ショップ」) など、このページの主題や目的を示していることを確認してください。
  3. サイトのほかのページを 2、3 ページ開き、タイトルでページを区別できることを確認してください。サイト名より前にそのページ固有の部分を置くのは良い方法ですが、必須ではありません。
  4. シングルページアプリケーションのように、新しいページを読み込まずに内容が変わる場合は、タイトルもそれに合わせて変わることを確認してください。
合格の条件
ページのタイトルがその主題や目的を示し、ほかのページと区別できます。
不合格の条件
ページにタイトルがないか、汎用的なタイトル、ファイル名、またはほかのページと同じタイトルであるため、WCAG 2.4.2 を満たしません。

これを検査するルール：page-title-present, page-title-patterns

この手順では次も評価します：

  • <title> 要素があり、空でない
  • ページタイトルのパターンの確認 (汎用的、重複、ページ間でテンプレートに頼りすぎ)

2.4.3 フォーカス順序

レベル A

Tab キーと Shift+Tab によるフォーカスの移動が、ページの意味を保ち、操作できる順序に従っている
  • 人だけが確認できる
  • 必要なもの：キーボード
  1. ページを再読み込みし、フォーカスの移動先を見ながら、フォーカスがページ全体を一巡するまで Tab キーを繰り返し押してください。
  2. その順序を、ページを読んで操作する順序と比べてください。たとえば、フォームのフィールドはラベルの順に、作業の手順はその順番どおりに移動するかを見ます。
  3. Shift+Tab でページを戻り、フォーカスが同じ経路を逆にたどることを確認してください。
  4. 順序が読む順序と異なる場合は、フォームのフィールドより先に送信ボタンに到達するなど、それによって意味が変わったり操作できなくなったりするかを確認してください。
合格の条件
見た目の順序と多少異なる箇所があっても、フォーカスがページの意味を保ち、すべての部分を操作できる順序でページ内を移動します。
不合格の条件
フィールドが本来の順序どおりに入力されないなど、フォーカスがページ内をあちこちに移動し、意味や操作が変わってしまうため、WCAG 2.4.3 を満たしません。
開いたダイアログ、メニュー、セクションにフォーカスが移動し、ダイアログがページを覆っている間はその中にとどまり、閉じると元に戻る
  • 人だけが確認できる
  • 必要なもの：キーボード
  1. ページにある各ダイアログ、メニュー、ドロップダウン、折りたたまれたセクションを、それを開くコントロールで Enter または Space を押して、キーボードで開いてください。
  2. Tab キーを 1 回押し、フォーカスが、背後や離れた場所にあるものではなく、開いたものの中に移る (またはすでにその中にある) ことを確認してください。
  3. ページを覆うダイアログでは、すべてのコントロールを一巡するまで Tab キーを押し、フォーカスが背後のページに移らずダイアログの中にとどまることを確認してください。
  4. Escape または閉じるボタンで閉じ、フォーカスがそれを開いたコントロール、または次に移るのが妥当な場所に戻ることを確認してください。
合格の条件
フォーカスが開いたものの中に移動し、ダイアログがページを覆っている間はその中にとどまり、閉じると元の場所に戻ります。
不合格の条件
フォーカスが開いたものの背後に残る、ダイアログから背後のページへ移る、または閉じたときにページの先頭に移るため、順序が画面上の表示に沿わなくなり、WCAG 2.4.3 を満たしません。
閉じている、隠れている、または画面外にあるコンテンツにフォーカスが止まらない
  • 人だけが確認できる
  • 必要なもの：キーボード, ブラウザーの開発者ツール
  1. メニューやダイアログを閉じてからページを再読み込みし、フォーカスの位置を見ながら Tab キーでページ全体を移動してください。
  2. 1 回以上のキー操作の間、フォーカスが消えたように見えるたびに控えてください。
  3. そうした各停止位置で、開発者ツールの [Console] に document.activeElement と入力し、表示された要素が閉じたメニュー、隠れたパネルの中にあるか、画面外にあるかを確認してください。
  4. フォーカスを受け取ると現れるスキップリンクは除外してください。フォーカスを受け取った時点で表示されます。
合格の条件
すべてのタブストップが、目に見えるもの、またはスキップリンクのようにフォーカスを受け取ると現れるものの上にあります。
不合格の条件

2.4.4 リンクの目的 (文脈内)

レベル A

各リンクの目的が、リンクテキストだけで、またはリンクテキストとそれを含む文、段落、リスト項目、表のセルから判断できる
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー
  1. スクリーンリーダーのリンク一覧でページのリンクを一覧にするか、Tab キーでリンクを順に移動して、開発者ツールのアクセシビリティ ペインで各リンクの Name を読んでください。
  2. 空の名前、「こちら」「続きを読む」「PDF」、アイコンのファイル名など、移動先や働きを示していない名前のリンクを控えてください。
  3. それぞれについて、リンクを含む文、段落、リスト項目、表のセル、またはそのセルの表見出しを読み、それで目的が明らかになるか確認してください。
  4. 対象となる文脈は、リンクを含む文、段落、リスト項目、表のセル、その表のセルの見出しセル、リンクが属する見出し、および aria-describedby でリンクに関連付けられたテキストです。別の列の段落など、リンクの近くにあるだけのテキストは対象になりません。
  5. 同じ名前で異なる場所へ移動するリンクが、文脈によって区別できることを確認してください。
合格の条件
すべてのリンクの目的が、名前だけで、または名前とそれを含む文、段落、リスト項目、表のセルから明らかです。
不合格の条件
リンクに名前がないか、「続きを読む」のような名前で、周囲のどこにもその目的の説明がないため、WCAG 2.4.4 を満たしません。

これを検査するルール：link-name-present, link-name-quality

この手順では次も評価します：

  • リンクがアクセシブルな名前を公開している (名前のないリンクには判断すべき目的がない)
  • リンクテキストが、説明的でない汎用的な語句として知られるものではない (手がかりのみ。周囲の文脈で十分かは検証しない)

2.4.6 見出し及びラベル

レベル AA

見出しが、その後に続くコンテンツを説明している
  • 人だけが確認できる
  • 必要なもの：スクリーンリーダー
  1. スクリーンリーダーの見出し一覧、HeadingsMap などのブラウザー拡張機能、または開発者ツールのアクセシビリティツリーで、ページの見出しを一覧にしてください。
  2. 各見出しと、その下のコンテンツを読んでください。
  3. 各見出しが、仮の文字列、ファイル名、何の見出しにもなりうる語ではなく、そのコンテンツの主題を示していることを確認してください。

ラベルがフィールドを説明しており、同じラベルのフィールドを区別できる
  • 人だけが確認できる
  • 必要なもの：ブラウザーのみ

合格の条件

不合格の条件
ラベルがフィールドの目的を示していないか、複数のフィールドが同じラベルを持ち、それらを区別するものがないため、WCAG 2.4.6 を満たしません。

2.4.7 フォーカスの可視化

レベル AA

  • 必要なもの：キーボード
  1. ページを再読み込みし、Tab キーでページ全体をゆっくり移動してください。
  2. 各停止位置で、アウトライン、色の変化、下線、その他の目に見える変化によって、どの要素にフォーカスがあるかが見えることを確認してください。
  3. フォーカスの移動にはマウスではなくキーボードを使ってください。ブラウザーは、マウスでクリックした要素のフォーカスを Tab キーで到達した要素とは異なる方法で表示するため、マウスでのテストではここでは何も証明できません。
  4. フォーカスがどこにあるかわからない停止位置と、1 回以上のキー操作の間フォーカスが消えたように見える箇所をすべて控えてください。
  5. 矢印キーを使うメニュー、ダイアログ、ウィジェットの中でも同じことを行ってください。
  6. Windows でコントラストテーマをオンにし、いくつかの停止位置で繰り返してください。box-shadow や背景色だけで描かれたフォーカスのスタイルは、そのモードでは消えます。WCAG はそこで表示されることを求めていませんが、ベストプラクティスの問題として記録してください。
合格の条件
すべての停止位置で、どの要素にフォーカスがあるかが見えます。
不合格の条件

これを検査するルール：css-hidden-focus, css-focus-indicator-suppressed, focus-not-removed-by-script

この手順では次も評価します：

  • Tab キーで移動できる要素が CSS によって視覚的に隠されている
  • CSS が代わりの表示を描かずにフォーカスインジケータを消していない
  • インラインのフォーカスハンドラーが、フォーカスを受け取った要素からフォーカスを外さない (手がかりのみ。スクリプトから追加されたリスナーは静的には見えない)

3.1.1 ページの言語

レベル A

ページの主な言語がマークアップで示され、それが正しい
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. 開発者ツールの [Elements] パネルで、<html> 要素の lang 属性を読んでください。

  3. <html> に xml:lang もある場合は、両方が同じ言語を示していることを確認してください。
  4. シングルページアプリケーションでは、インターフェースの言語を切り替え、lang もそれに合わせて変わることを確認してください。スクリーンリーダーはその言語の音声がインストールされている場合にだけ音声を切り替えるため、聞こえる内容だけでなく、マークアップで判断してください。

不合格の条件

この手順では次も評価します：

  • <html> に空でない有効な lang 属性がある
  • <html> に lang と xml:lang の両方がある場合、同じ主言語を宣言している

3.1.2 一部分の言語

レベル AA

  2. それぞれについて、開発者ツールの [Elements] パネルで、その要素またはそれを囲む要素に、その言語のコードを持つ lang 属性があることを確認してください。
  3. 固有名詞、技術用語、英語における「café」のようにページの言語の一部になった語は除外してください。
  4. いくつかをスクリーンリーダーで聞き、発音が切り替わることを確認してください。
合格の条件

不合格の条件
ほかの言語の文章や語句にその言語が指定されていないか、誤ったコードが指定されているため、誤った発音で読み上げられ、WCAG 3.1.2 を満たしません。

これを検査するルール：valid-lang

この手順では次も評価します：

レベル A

  • ルールが一部を判定する
  • 必要なもの：キーボード, スクリーンリーダー

不合格の条件

3.3.2 ラベル又は指示

  2. それぞれに、ホバーや入力をしなくても見えるラベルがあることを確認してください。入力すると消えるプレースホルダーや、ホバー時に表示される title だけではいけません。

不合格の条件

  • フォームコントロールにラベルまたは指示 (label/aria-label/aria-labelledby/title/placeholder) がある

3.3.8 アクセシブルな認証 (最低限)

レベル AA

回避する手段が提供されていない限り、サインインに何かを記憶する、書き写す、解くことが求められない
  • 人だけが確認できる
  • 必要なもの：ブラウザーのみ
  1. テスト用アカウントで、サイトが提供するサインインや本人確認の方法をそれぞれ試してください。
  2. 何かを記憶する (パスワード)、書き写す (別のデバイスに届いたコード)、解く (パズル、計算、画像の選択) ことを求める段階をすべて控えてください。
  3. パスワードやコードについては、記憶したり入力し直したりしなくて済むように、貼り付けができ、パスワードマネージャーで入力できることを確認してください。
  4. パスワードマネージャーが実際にフィールドに入力することを確認してください。ユーザー名とパスワードのフィールドには autocomplete="username" と autocomplete="current-password" (または new-password) が必要で、ワンタイムコードのフィールドは autocomplete="one-time-code" があると最もよく機能します。
  5. コードが 1 桁ずつのボックスに分かれている場合は、最初のボックスにコード全体を貼り付け、すべてのボックスに入力されることを確認してください。貼り付けを禁止するボックスや、1 文字ずつしか受け付けないボックスは不合格です。

合格の条件
何かを記憶する、書き写す、解くことを求めるサインインの各段階で、貼り付けとパスワードマネージャーが使えるか、別の方法が提供されているか、物体や利用者自身のコンテンツの認識だけが求められます。
不合格の条件
貼り付けを禁止するコードのフィールドなど、回避する手段がないまま、サインインに何かを記憶する、書き写す、解くことが求められるため、WCAG 3.3.8 を満たしません。

これを検査するルール：password-paste-enabled

この手順では次も評価します：

  • パスワードやワンタイムコードのフィールドが貼り付けを取り消さず、パスワードマネージャーやクリップボードから入力できる

4.1.2 名前 (name)・役割 (role)・値 (value)

レベル A

すべてのリンク、コントロール、フレーム、ダイアログに、その目的を示す名前がある

  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー

  2. それぞれについて、開発者ツールのアクセシビリティ ペインで Name を読むか、スクリーンリーダーが読み上げる内容を聞いてください。
  3. ブラウザーとスクリーンリーダーの 2 つの組み合わせで名前を確認してください。aria-labelledby、コントロールを囲むラベル、CSS の content から作られる名前は、組み合わせによって異なることがあります。

合格の条件
すべてのリンク、コントロール、フレーム、ダイアログに、その目的を示す名前があります。
不合格の条件
リンク、コントロール、フレーム、ダイアログに名前がないか、名前がその目的を示していないため、支援技術がロールしか読み上げず、WCAG 4.1.2 を満たしません。

これを検査するルール：form-control-programmatic-label-present, link-name-present, button-name-present, input-image-alt-present, binary-control-name-present, combobox-name-present, dialog-name-present, menuitem-name-present, tab-name-present, slider-name-present, textbox-name-present, searchbox-name-present, spinbutton-name-present, listbox-name-present, option-name-present, treeitem-name-present, aria-role-name-present, iframe-name-present, identical-iframes-same-purpose, iframe-title-unique, summary-name-present, tooltip-name-present, aria-braille-equivalent

この手順では次も評価します：

  • フォームコントロールがアクセシブルな名前 (label/aria-label/aria-labelledby/title/placeholder) を公開している
  • リンクがアクセシブルな名前 (内容のテキスト / aria-label / aria-labelledby / title) を公開している
  • ボタンがアクセシブルな名前 (内容のテキスト / aria-label / aria-labelledby / title / value) を公開している
  • 画像ボタン (<input type="image">) がアクセシブルな名前 (aria-labelledby / aria-label / alt / title) を公開している
  • チェックボックスがアクセシブルな名前 (label / aria-label / aria-labelledby / title) を公開している
  • ラジオボタンがアクセシブルな名前 (label / aria-label / aria-labelledby / title) を公開している
  • スイッチがアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • コンボボックスがアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • ダイアログがアクセシブルな名前 (aria-labelledby / aria-label / title / 内容) を公開している
  • メニュー項目がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • タブがアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • スライダーがアクセシブルな名前 (label / aria-label / aria-labelledby / title / 内容) を公開している
  • テキストボックス (role="textbox") がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • 検索ボックス (role="searchbox") がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • スピンボタン (role="spinbutton") がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • リストボックス (role="listbox") がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • 選択肢 (role="option") がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • ツリー項目 (role="treeitem") がアクセシブルな名前 (内容 / aria-label / aria-labelledby / title) を公開している
  • 特定の ARIA のウィジェットロールやコンテナーロール (scrollbar、toolbar、tablist、radiogroup、tree、grid、menu、menubar) がアクセシブルな名前を公開している
  • <iframe>/<frame> 要素がアクセシブルな名前 (aria-label / aria-labelledby / title) を公開している
  • アクセシブルな名前が同じ <iframe>/<frame> 要素が、同じリソースを埋め込んでいる
  • <summary> 要素がアクセシブルな名前を公開している
  • role="tooltip" の要素がアクセシブルな名前を公開している
  • aria-braillelabel/aria-brailleroledescription に、点字以外の同等のものがある
すべてのコントロールのロールがその働きを示し、コントロールが互いに入れ子になっていない
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー
  1. ページ上の各コントロールについて、使ったときの働きを控えてください。ページを開く (リンク)、ページ上で何かを実行する (ボタン)、切り替える (チェックボックスやスイッチ)、リストを開く (メニューやコンボボックス) などです。
  2. 開発者ツールのアクセシビリティ ペインで Role を読むか、スクリーンリーダーで聞き、ロールが働きと一致していることを確認してください。
  3. div や span で作られたカスタムコントロール、ボタンとして使われているリンク、リンクとして使われているボタンに注意してください。
  4. リンクの中のボタンのように、コントロールが別のコントロールを内部に含んでいないこと、またタブやボタンのように子要素がプレゼンテーション用となるコントロールが、フォーカス可能なものを含んでいないことを確認してください。
合格の条件
すべてのコントロールのロールがその働きを示し、ほかのコントロールの中に入れ子になったコントロールはありません。
不合格の条件
コントロールにロールがないか誤ったロールがある (ロールのないクリック可能な div、ボタンとして機能するリンク)、または内部に別のコントロールを含んでいるため、WCAG 4.1.2 を満たしません。

これを検査するルール：aria-roles-valid, aria-deprecated-role, nested-interactive-controls-absent, presentational-children-focusable-absent

この手順では次も評価します：

  • 明示的な role 属性が、抽象ロールでない実在の ARIA ロールに解決される
  • 明示的な role 属性が、非推奨の ARIA ロールを使っていない
  • インタラクティブなコントロールが、ほかのインタラクティブなコントロールを含んでいない
  • 子要素がプレゼンテーション用となるロールが、シーケンシャルなフォーカスナビゲーションの対象となるコンテンツを含んでいない
すべてのコントロールの状態と値が公開され、画面上の表示に合わせて変わる
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール, スクリーンリーダー, キーボード
  1. チェックボックス、スイッチ、ラジオボタン、展開できるセクションやメニュー、タブ、スライダー、選択された項目、押された状態のボタンなど、状態や値を持つコントロールを見つけてください。
  2. 開発者ツールのアクセシビリティ ペインでそれぞれの状態と値を読むか、スクリーンリーダーで聞いてください。checked、expanded、selected、pressed、現在の項目 (aria-current)、スライダーやスピンボタンの現在の値です。
  3. それぞれをキーボードで変更し、読み上げられる状態や値が見た目に合わせて変わることを確認してください。
  4. 展開できるコントロールについては、それが開くものが表示されている間だけ展開状態と伝えることを確認してください。
合格の条件
すべてのコントロールの状態と値が公開され、画面上の表示に合わせて変わります。
不合格の条件
常に未チェックと読み上げられるカスタムチェックボックスのように、コントロールの状態や値が公開されていないか、画面上で変わっても変わらないため、WCAG 4.1.2 を満たしません。

これを検査するルール：aria-required-attr, aria-conditional-attr, aria-checked-state-mismatch, aria-expanded-state-mismatch

この手順では次も評価します：

  • 必須の状態やプロパティが一意に決まるロールが、それを持っている (例: role="checkbox" に aria-checked がある)
  • aria-errormessage が、aria-invalid が false でも未指定でもない場合にだけ使われている
  • ネイティブのチェックボックスやラジオボタンの aria-checked が、実際の checked/indeterminate の状態と一致している (手がかりのみ。静的なマークアップでは後からの JS によるハイドレーションを排除できない)
  • aria-expanded が、aria-controls が示すコンテンツが表示されているかと一致している (手がかりのみ。静的なマークアップは遷移の途中や未実行のスクリプトの状態をとらえる可能性がある)
ARIA 属性が実在し、有効で、その場所で許可されており、フォーカス可能なものが支援技術から隠されていない
  • ルールが一部を判定する
  • 必要なもの：ブラウザーの開発者ツール
  1. 開発者ツールの [Elements] パネルで、マークアップから aria- と role= を検索し、それぞれの使われ方を確認してください。
  2. 各 aria-* 属性が実在するものであり、有効な値を持ち、その要素のロールで許可されていることを確認してください。
  3. aria-labelledby、aria-describedby、aria-controls などが指す id が、それぞれ 1 つずつ存在することを確認してください。
  4. aria-hidden="true" を持つ要素の中にフォーカスを受け取るものがないこと、また <body> が隠されていないことを確認してください。
合格の条件
ARIA 属性が実在し、有効で、その場所で許可されており、参照される id は一意で、フォーカス可能なものは隠されていません。
不合格の条件
ARIA 属性のつづりが誤っている、値が無効である、またはそのロールで許可されていない、参照する id が存在しないか重複している、またはフォーカス可能なものが支援技術から隠されているため、WCAG 4.1.2 を満たしません。

これを検査するルール：aria-hidden-focus, aria-valid-attr, aria-valid-attr-value, aria-allowed-attr, aria-prohibited-attr, aria-hidden-body, duplicate-id-aria

この手順では次も評価します：

  • aria-hidden のサブツリーにフォーカス可能なコンテンツがある
  • 存在するすべての aria-* 属性の名前が、実在し定義された ARIA 属性である
  • 認識されるすべての aria-* 属性に、宣言された型に合う値がある
  • 存在する aria-* 属性が、要素の明示的なロールで許可されている
  • 名前付けのための ARIA 属性が、それを禁止するロールで使われていない
  • 文書の <body> に aria-hidden="true" がない
  • ARIA の ID 参照属性が参照する ID が、文書内で一意である

4.1.3 ステータスメッセージ

レベル AA

ステータスメッセージが、フォーカスを移さずに支援技術によって読み上げられる
  • 人だけが確認できる
  • 必要なもの：スクリーンリーダー
  1. 「カートに追加しました」、検索結果の件数、「保存しました」、進行状況、送信後に一覧表示されるフォームのエラーなど、ページがフォーカスを移さずに表示するメッセージを見つけてください。
  2. スクリーンリーダーをオンにし、各メッセージを表示させる操作を行って、メッセージを発生させてください。
  3. フォーカスがメッセージに移ることなく、スクリーンリーダーがメッセージを読み上げることを確認してください。
  4. 2 つ目のブラウザーとスクリーンリーダーの組み合わせでも繰り返してください。ライブリージョンは、スクリーンリーダーのサポートの中でも特に一貫性の低い部分です。
  5. 何も読み上げられない場合は、開発者ツールで、メッセージが role="status"、role="alert"、または aria-live を持つ要素の中にあり、その要素が隠されていないことを確認してください。role="status" や aria-live のリージョンは、メッセージが入れられる前から、空の状態でページ上に存在している必要があります。role="alert" を持つ要素は、メッセージと一緒に追加された場合でも、たいてい読み上げられます。
  6. フォーカスを受け取るメッセージや、新しいページとともに表示されるメッセージは除外してください。それらはステータスメッセージではなく、ほかの達成基準で確認します。
合格の条件
すべてのステータスメッセージが、フォーカスがそれに移ることなく、スクリーンリーダーによって読み上げられます。
不合格の条件
ステータスメッセージが画面に表示されるのに、スクリーンリーダーがそれを読み上げないため、WCAG 4.1.3 を満たしません。

これを検査するルール：live-region-announcements

この手順では次も評価します：

  • ライブリージョンが aria-hidden や inert で支援技術から隠されておらず、busy のまま放置されていない (手がかりのみ。ページがそれをステータスメッセージに使っているかは人による判断)
  • ライブリージョンが、アクセシビリティツリーに追加された後でステータスメッセージを受け取っており、メッセージと一緒に追加されたり表示されたりしていない (手がかりのみ。ライブリージョンのフックが必要で、スクリーンリーダーによって挙動が異なる)
