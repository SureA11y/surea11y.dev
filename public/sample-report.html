ℹ img-alt-quality (Needs review, minor severity)
WCAG 1.1.1
Selector: html > body > main > img:nth-of-type(2)
The text alternative of this <img> looks like a file name. — A file name tells someone who can’t see the image nothing about it (WCAG failure F30). Replace it with text that says what the image shows or, on a link or button, where it leads or what it does. Keep it only if the file name is itself what the image shows, such as a screenshot of a file list.

Likely fails: A file name, a web address or a generic word does not say what the image shows. Caution: The word may be all the image shows, such as an image of that word.

How to check
  1. Find the image the report names and read its alt text (the report gives the reason it looked suspect, if any).
  2. Look at the image and its context, and ask what it shows that matters to the page.
  3. If the text alternative only names the image, as is common for charts and diagrams, the details may be given elsewhere: in a caption, text or a table next to it, or a link beside it. That counts only if a screen reader user can find it from the image and it gives everything the image shows.
  4. Decide whether the alt says what matters, or names the image while that description gives the rest; a file name, web address or generic word such as "image" does neither.

Passes: The alt text conveys what the image shows that a user needs, or it names the image and a description a screen reader user can reach from it gives the rest.

Fails: Neither the alt text nor a description reachable from the image conveys the image's content (for example the alt is a file name, address or generic word), which fails WCAG 1.1.1 (F30).

ℹ manual-review (Needs review, moderate severity)
WCAG 2.1.1WCAG 2.4.3WCAG 2.4.7
Selector: html
Check keyboard navigation and focus order by hand. — Tab through the page and check that every interactive element can be reached and used with the keyboard, and that focus can always leave it again; that the focus order follows the reading order, also after a script opens or adds content; and that the focus is always visible.
How to check
  1. Click the browser's address bar, then press Tab repeatedly to move through every link and control on the page.
  2. At each stop, check that you can see where focus is, and that the order follows the reading order of the page.
  3. Operate each control with the keyboard (Enter, Space, arrow keys) and open and close menus and dialogs.
  4. Where something cannot be reached or used with the keyboard, check whether the page offers another way to do the same with the keyboard alone, such as previous and next buttons for a carousel, or move up and move down buttons for a list you can drag. It only counts if it does everything the mouse can.
  5. Check that focus never gets stuck inside a component and that Escape or Tab lets you move on.

Passes: Everything works with the keyboard, directly or through another way that does the same job, focus moves in a sensible order and is always visible, and it never gets stuck.

Fails: Something cannot be reached or used with the keyboard in any way, focus traps the user, the order is confusing, or focus is invisible, which fails WCAG 2.1.1, 2.1.2, 2.4.3 or 2.4.7.
