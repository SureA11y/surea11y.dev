ℹ invalid-field-error-message (Requiere revisión, gravedad grave)
WCAG 3.3.1
Selector: #email
Este campo está marcado como no válido, pero el mensaje de error que nombra aria-errormessage está oculto. — Mostrar el mensaje de error mientras el campo no sea válido.

Probable fallo: El mensaje de error vinculado al campo está oculto, así que probablemente no se comunica el error.

Cómo comprobarlo
  1. Hacer que el campo no sea válido como lo haría un usuario (enviar el formulario vacío o escribir un valor erróneo).
  2. Buscar el mensaje de error al que apunta el campo (su aria-errormessage) y comprobar si aparece en pantalla.
  3. Si no aparece, buscar cualquier texto que le diga qué está mal: en la etiqueta, junto al campo o en un resumen en la parte superior del formulario.
  4. Con un lector de pantalla, desplazarse hasta el campo y escuchar el error.

Cumple: El error se muestra en texto, y se anuncia, en algún lugar vinculado al campo, aunque no sea en el mensaje que indica aria-errormessage.

Falla: Ningún texto le dice qué campo está mal ni por qué, o a quien usa lector de pantalla no se le comunica, lo que incumple WCAG 3.3.1.

Comprender 3.3.1 Error Identification

ℹ img-alt-quality (Requiere revisión, gravedad menor)
WCAG 1.1.1
Selector: html > body > main > img:nth-of-type(2)
La alternativa textual de este <img> parece un nombre de archivo. — Un nombre de archivo no le dice nada sobre la imagen a quien no puede verla (fallo F30 de WCAG). Sustituirlo por un texto que diga qué muestra la imagen o, en un enlace o botón, adónde lleva o qué hace. Mantenerlo solo si el nombre de archivo es lo que muestra la imagen, como en una captura de pantalla de una lista de archivos.

Probable fallo: Un nombre de archivo, una dirección web o una palabra genérica no dice lo que muestra la imagen. Atención: La palabra puede ser todo lo que muestra la imagen, como una imagen de esa palabra.

Cómo comprobarlo
  1. Localizar la imagen que indica el informe y leer su texto alternativo (el informe da el motivo por el que pareció sospechoso, si lo hay).
  2. Observar la imagen y su contexto, y preguntarse qué muestra que sea importante para la página.
  3. Si la alternativa textual solo nombra la imagen, como es habitual en gráficos y diagramas, los detalles pueden estar en otro sitio: en un pie, un texto o una tabla junto a ella, o en un enlace al lado. Solo cuenta si un usuario de lector de pantalla puede encontrarlo desde la imagen y da todo lo que muestra la imagen.
  4. Decidir si el alt dice lo importante, o nombra la imagen mientras esa descripción da el resto; un nombre de archivo, una dirección web o una palabra genérica como «imagen» no hace ninguna de las dos cosas.

Cumple: El texto alt transmite lo que muestra la imagen y necesita el usuario, o nombra la imagen y una descripción a la que un usuario de lector de pantalla llega desde ella da el resto.

Falla: Ni el texto alt ni una descripción accesible desde la imagen transmiten su contenido (por ejemplo, el alt es un nombre de archivo, una dirección o una palabra genérica), lo que incumple WCAG 1.1.1 (F30).

ℹ duplicate-id (Requiere revisión, gravedad moderada) × 2
WCAG 4.1.1
Selector: html > body > main > form > input:nth-of-type(2)
El id «code» se usa en 2 elementos del mismo árbol. — Dar a cada elemento su propio id. Un id duplicado rompe <label for>, los enlaces de fragmento, getElementById y todo atributo de referencia por id: todos resuelven solo a la primera coincidencia.

Probablemente cumple: WCAG 2.2 eliminó el criterio con el que se detectó esto. Atención: El defecto en sí sigue rompiendo lo que depende de él, y una norma que mantiene el criterio lo da por incumplido.

Cómo comprobarlo
  1. Inspeccionar los elementos que indica el informe y anotar el id compartido.
  2. Comprobar si algo remite a ese id: el for de un label, un atributo aria-* como aria-labelledby, o un enlace a #the-id.
  3. Si algo remite a él, seguir la referencia (hacer clic en el label o en el enlace, o leer el nombre en el panel Accesibilidad) y comprobar que llega al elemento previsto.
  4. Comprobar qué versión de WCAG y qué norma aplica la auditoría; con WCAG 2.2, o con 2.0/2.1 y la fe de erratas de 2023, el 4.1.1 se cumple para HTML.

Cumple: Nada falla por el duplicado (las referencias llegan al elemento previsto) y la auditoría usa WCAG 2.2, o 2.0/2.1 con la fe de erratas, con las que el 4.1.1 se cumple.

Falla: Un label, una referencia ARIA o un enlace llega al elemento equivocado (WCAG 1.3.1 o 4.1.2), o la auditoría sigue una norma que conserva el texto del 4.1.1, como EN 301 549 V3.2.1, en la que los id duplicados incumplen el 4.1.1 (F77).

Cómo comprobarlo
