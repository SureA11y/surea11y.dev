ℹ invalid-field-error-message (Prüfung nötig, Schweregrad schwerwiegend)
WCAG 3.3.1
Selektor: #email
Dieses Feld ist als ungültig markiert, aber die von aria-errormessage genannte Fehlermeldung ist ausgeblendet. — Zeigen Sie die Fehlermeldung an, solange das Feld ungültig ist.

Wahrscheinlich nicht erfüllt: Die mit dem Feld verknüpfte Fehlermeldung ist ausgeblendet; der Fehler wird daher wahrscheinlich nicht mitgeteilt.

So prüfen Sie es
  1. Machen Sie das Feld so ungültig, wie es Nutzende tun würden (Formular leer absenden oder einen falschen Wert eingeben).
  2. Suchen Sie die Fehlermeldung, auf die das Feld verweist (sein aria-errormessage), und prüfen Sie, ob sie auf dem Bildschirm erscheint.
  3. Erscheint sie nicht, suchen Sie nach Text, der sagt, was falsch ist: in der Beschriftung, neben dem Feld oder in einer Zusammenfassung oben im Formular.
  4. Navigieren Sie mit einem Screenreader zum Feld und achten Sie auf den Fehler.

Erfüllt: Der Fehler wird als Text angezeigt und angesagt, an einer mit dem Feld verknüpften Stelle, auch wenn es nicht die Meldung ist, die aria-errormessage nennt.

Nicht erfüllt: Kein Text sagt, welches Feld falsch ist und warum, oder Screenreader-Nutzende erfahren es nicht; das verstößt gegen WCAG 3.3.1.

WCAG 3.3.1 Error Identification verstehen

ℹ img-alt-quality (Prüfung nötig, Schweregrad gering)
WCAG 1.1.1
Selektor: html > body > main > img:nth-of-type(2)
Die Textalternative dieses <img> sieht wie ein Dateiname aus. — Ein Dateiname sagt jemandem, der das Bild nicht sieht, nichts darüber (WCAG-Fehler F30). Ersetzen Sie ihn durch einen Text, der sagt, was das Bild zeigt, oder bei einem Link oder Button, wohin er führt oder was er tut. Behalten Sie ihn nur, wenn der Dateiname selbst das ist, was das Bild zeigt, etwa bei einem Screenshot einer Dateiliste.

Wahrscheinlich nicht erfüllt: Ein Dateiname, eine Webadresse oder ein allgemeines Wort sagt nicht, was das Bild zeigt. Achtung: Das Wort kann alles sein, was das Bild zeigt, etwa ein Bild genau dieses Worts.

So prüfen Sie es
  1. Suchen Sie das im Bericht genannte Bild und lesen Sie seinen Alternativtext (der Bericht nennt den Grund, warum er verdächtig wirkte, falls es einen gibt).
  2. Betrachten Sie das Bild und seinen Kontext und fragen Sie sich, was es zeigt, das für die Seite wichtig ist.
  3. Nennt die Textalternative das Bild nur, wie bei Diagrammen und Schaubildern üblich, können die Details anderswo stehen: in einer Bildunterschrift, einem Text oder einer Tabelle daneben oder hinter einem Link daneben. Das zählt nur, wenn Screenreader-Nutzer sie von dem Bild aus finden und sie alles wiedergeben, was dem Bild zeigt.
  4. Entscheiden Sie, ob der alt-Text das Wichtige sagt oder das Bild benennt, während diese Beschreibung den Rest liefert; ein Dateiname, eine Webadresse oder ein allgemeines Wort wie „Bild“ tut keines von beidem.

Erfüllt: Der alt-Text vermittelt, was das Bild zeigt und der Nutzer braucht, oder er benennt das Bild und eine Beschreibung, die Screenreader-Nutzer von ihm aus erreichen, liefert den Rest.

Nicht erfüllt: Weder der alt-Text noch eine vom Bild aus erreichbare Beschreibung vermittelt seinen Inhalt (etwa ist der alt-Text ein Dateiname, eine Adresse oder ein allgemeines Wort); das verstößt gegen WCAG 1.1.1 (F30).

ℹ duplicate-id (Prüfung nötig, Schweregrad mittel) × 2
WCAG 4.1.1
Selektor: html > body > main > form > input:nth-of-type(2)
Die ID „code“ wird an 2 Elementen im selben Baum verwendet. — Geben Sie jedem Element eine eigene ID. Eine doppelte ID bricht <label for>, Sprungmarken, getElementById und jedes ID-Referenz-Attribut – alle greifen nur auf den ersten Treffer zu.

Wahrscheinlich erfüllt: WCAG 2.2 hat das Kriterium gestrichen, nach dem dies gefunden wurde. Achtung: Der Fehler selbst beeinträchtigt weiterhin, was davon abhängt, und eine Norm, die das Kriterium beibehält, wertet ihn als Verstoß.

So prüfen Sie es
  1. Untersuchen Sie die im Bericht genannten Elemente und notieren Sie die gemeinsame id.
  2. Prüfen Sie, ob etwas auf diese id verweist: das for eines Labels, ein aria-*-Attribut wie aria-labelledby oder ein Link auf #the-id.
  3. Verweist etwas darauf, folgen Sie dem Verweis (klicken Sie auf das Label oder den Link oder lesen Sie den Namen im Bereich „Barrierefreiheit“) und prüfen Sie, ob er das beabsichtigte Element erreicht.
  4. Prüfen Sie, welche WCAG-Version und welchen Standard die Prüfung anwendet; unter WCAG 2.2 oder 2.0/2.1 mit den Errata von 2023 ist 4.1.1 für HTML erfüllt.

Erfüllt: Durch das Duplikat geht nichts kaputt (Verweise erreichen das beabsichtigte Element) und die Prüfung verwendet WCAG 2.2 oder 2.0/2.1 mit den Errata, unter denen 4.1.1 erfüllt ist.

Nicht erfüllt: Ein Label, ein ARIA-Verweis oder ein Link erreicht das falsche Element (WCAG 1.3.1 oder 4.1.2), oder die Prüfung folgt einem Standard, der den Text von 4.1.1 beibehält, etwa EN 301 549 V3.2.1, wonach doppelte ids gegen 4.1.1 verstoßen (F77).
